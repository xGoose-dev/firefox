# xgoose MCP (Firefox preview)

Connect Codex to the page tools in your xgoose Firefox extension. Requires Node.js 22.19 or later and a Firefox build with Local MCP control.

In extension settings, expand Advanced, enable Local MCP control and save. Then run:

```sh
codex mcp add xgoose -- npx --yes xgoose-mcp@next --port 8765
```

The default port is 8765; use the same port in both settings. Restart the Codex MCP connection after adding or changing its configuration. The `next` tag contains the preview package.

For manual configuration, add this to your Codex MCP settings. The longer timeout supports page tools that wait for results:

```toml
[mcp_servers.xgoose]
command = "npx"
args = ["--yes", "xgoose-mcp@next", "--port", "8765"]
tool_timeout_sec = 660
```

You can also install the command globally with `npm install -g xgoose-mcp@next`, then use `xgoose-mcp --port 8765` as your MCP server command. Run `xgoose-mcp --help` for setup options.

Codex launches the stdio adapter automatically. Adapters share a loopback broker and one Firefox profile per port. The broker exits after 60 seconds with no MCP clients. The extension reconnects when Codex starts it again.

Start one `start_session({includeTabs:true})` per agent/task. This returns the session ID and a compact tab list together. Reuse that session ID across tabs; end with `end_session`. Each tab reports its active website skill names. Prefer existing tabs, `navigate_tab` for another URL, and `close_tab` for temporary task pages.

Call website functions directly with `call_skill({sessionId,tabId,skill,function,args})`. Known functions need no discovery call. For unfamiliar functions, `help_skill({sessionId,tabId,skill})` returns only function names and summaries. Add `function` for one full input schema; cache the returned `version` and optionally send `ifVersion` to get an `unchanged` response.

`list_page_tools` returns a compact directory by default. Add `name` for one full tool schema; `ifVersion` is supported here too. Other tools use `call_page_tool({sessionId,tabId,name,arguments})`. The bridge manages document bindings; callers do not need document IDs. The optional legacy `documentId` argument is still accepted. A `page_changed` error means nothing was executed: inspect `currentUrl` and call `list_tabs` to refresh the binding before continuing. Calls whose outcome is unknown are not replayed.

A small task with known arguments needs only `start_session(includeTabs:true) → call_skill → end_session`. The page panel can stay closed.

Each session appears once under MCP sessions in extension history. Signed-in tool requests, results and errors upload as external transcripts; anonymous records remain local. No model reasoning is generated by this package. Existing page permissions still apply, including Allow User Scripts for js_exec. Interrupted or unknown operations are not automatically replayed.

To build the Firefox development extension from source, run `npm ci` and `npm run build` at the repository root, then temporarily load `apps/firefox/dist/manifest.json` in Firefox `about:debugging`. Publishing this npm package does not publish the browser extension.
